# Каталог игр: реестр, hash-роутинг и модульные экраны

> **Status:** принято — решение владельца 2026-10-31 («каждая игра — отдельный модуль и реестр; hash-роутинг; вторая игра — змейка; без UI-фреймворка»). Развивает ADR-0007 (ESM/Vite), не пересматривает его.

## Что изменилось

Сайт стал аркадой: `index.html` — только оболочка (fx-слои, контейнер `#app`, точка входа `js/main.js`). Игры живут в `js/games/<id>/` и регистрируются в реестре `js/games/registry.js` — добавление игры это новый модуль + одна строка. Дескриптор игры — контракт `{ id, nameKey, tagKey, accent, mount, unmount }`: каталог рендерит карточки из реестра, роутер переключает экраны, не зная устройств игр.

## Навигация и жизненный цикл экрана

Hash-роутинг: `#/` — каталог, `#/hypercube` и `#/snake` — игры. Роутер на смене хеша вызывает `unmount()` активной игры, чистит контейнер и вызывает `mount(container)` следующей; единственный навигационный механизм — `hashchange`, перезагрузки и прямые ссылки работают на Pages как есть. Разметка экрана — `screen.html`, подключаемый Vite-импортом `?raw` (строка инлайнится в бандл); `mount` строит DOM, вешает обработчики и запускает экран. `unmount` обязан гасить таймеры и сеть (у Hyper-Cube — прощальное `bye`, чтобы соперник увидел выход, а не обрыв). Пригласительная ссылка онлайна теперь `?room=CODE#/hypercube` — параметр по-прежнему читается из `location.search`.

## Общий слой

Словарь i18n один на всю аркаду с префиксами по играм (`cat.*`, `sn.*`; ключи Hyper-Cube сохраняют исторические имена без префикса). Общие UI-механики вынесены в `js/ui.js` (`applyStaticI18n`, `wireSeg`), аудио `js/audio.js` общее. Ритуал i18n проверяет ключи всех HTML аркады: `index.html`, `js/catalog.html` и оба `screen.html`.

## Отклонённые альтернативы

- **UI-фреймворк (React/Vue)** — переписывание работающего, покрытого тестами P2P-слоя без выигрыша: эстетика и так кастомный CSS, а расширяемость даёт реестр, а не фреймворк. Вернуться к вопросу стоит, если игр станет много и экраны обрастут общими сложными UI-механиками.
- **Многостраничность (MPA)** — отдельные `index.html` на игру + `rollupOptions.input`: дублирование fx-оболочки, полные перезагрузки между каталогом и игрой.
- **Каталог в localStorage / «добавление игр» из UI** — для статического сайта без бэкенда фиктивно: добавление игры — это код в репозитории, и реестр делает его однострочным.

## Snake как проверка контракта

Вторая игра добавлена не ради галочки: змейка проверила, что дескриптор работает для игры другого жанра — canvas вместо DOM-поля, `keydown` на `window` с обязательным снятием в `unmount`, чистое ядро `core.js` под `node:test` (тот же паттерн детерминированного ГПСЧ, что у ИИ).
