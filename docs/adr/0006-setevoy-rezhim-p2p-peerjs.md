# Сетевой режим P2P: PeerJS-транспорт, host-авторитарная сессия, код комнаты

> **Status:** принято — все решения grilling-сессии «Мультиплеер p2p» от 2026-10-24 подтверждены владельцем (12 из 12 вопросов, единственная правка: пригласительная ссылка оставлена в v1).

## Транспорт: PeerJS, брокер только для рукопожатия

WebRTC DataChannel — единственный настоящий P2P для статического сайта. Рукопожатие идёт через публичный брокер PeerJS (CDN-скрипт с `defer`); после установления канала трафик идёт напрямую между устройствами, брокер больше не нужен. Если CDN недоступен, скрипт тихо не грузится и локальные режимы работают как раньше. Отклонённые альтернативы: ручной copy-paste-обмен оффер/ансвер (нулевые зависимости, но двухфазный обмен длинными кодами), собственный сигналинг-сервер (ломает принцип «статический сайт на GitHub Pages, ноль инфраструктуры»).

## Топология: host-авторитарная

Хост владеет `Match` и `GameCore`, валидирует каждый ход и после каждого изменения рассылает **снапшот** — полное сериализованное состояние (раунд, счёт, клетки, очередь хода, итог раунда). Гость — тонкий клиент со **строгим рендером**: ход отправляется и отображается только после подтверждения снапшотом, локальной мутации состояния нет. Один источник правды — нет расхождений и двойной валидации; задержка WebRTC (<100 мс) делает строгий рендер незаметным. Отклонённая альтернатива: симметричная синхронизация (оба исполняют логику, обмен только ходами) — риск расхождения и дублирование правил.

## Код комнаты и приглашение

Код комнаты — `HYP-XXXXXX` (6 символов алфавита без I, O, 0, 1) — и есть PeerJS-ID хоста: без таблиц соответствий, вероятность коллизии ничтожна. Приглашение — тем же кодом или ссылкой `?room=CODE`; ссылка открывает меню с выбранной ролью гостя и префиллом кода, подключение — явным кликом (без авто-подключения: внезапный коннект выглядит как ошибка, неясно что показывать при сбое).

## Роли, символы, матч

Хост всегда X, гость всегда O; стартёр чередуется по раундам штатной логикой `Match` (модуль не менялся). Матч полный: счёт раундов живёт в снапшоте. Переходы раунда («следующий раунд», «рестарт») инициирует любой игрок — хост применяет действие и рассылает снапшот. При намеренном выходе игрок отправляет `bye`: соперник возвращается в меню со статусом «соперник покинул комнату», а не с аварийным оверлеем.

## Обрыв связи

Оверлей «связь потеряна» с единственной кнопкой «в меню»; матч прерывается. Авто-reconnect (новый Peer = новый ID, нужен протокол переподключения) вырезан из v1 по YAGNI; так же вырезаны чат, наблюдатели, матчмейкинг и замещение выпавшего игрока ИИ.

## Модули: шов Session, адаптер Net

Протокол и синхронизация — в `js/session.js`: `Session.host({ core, match, send })` применяет ходы гостя к матчу, `Session.guest({ core, n, send })` держит match-подобное представление только для рендера. Транспорт — тонкий адаптер `js/net.js` над PeerJS с инъекцией конструктора `Peer`. Seam у Session настоящий: в тестах пара фейковых транспортов (`tests/session.test.js`), в браузере — Net. Отклонённая альтернатива: тестировать PeerJS-адаптер фейковым Peer — хрупко и проверяет чужой код.
